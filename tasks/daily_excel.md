# 毎日11:00の自動実行（試験運用）：Excelの作成だけ

## 目的
毎日11:00に、当月1日〜前日（完結した日）までの集計Excelを作り直す。数日間の試験運用で、使用量（Proプランの上限）が足りるかを確かめる。

## 事前許可（この試験運用に限る）
- エルメ管理画面から、フォーム回答CSV4つ（176252 / 178808 / 202523 / 205225）とProduct_selling CSVをダウンロードすることを、ユーザーが事前に許可した。読み取りだけで、エルメのデータは変更しない。
- Product_sellingの取得場所は、CLAUDE.mdの2章（2）のとおり（有料プラン限定 → ASP管理 → 成約状況、同名2つのうち一番下、友だち数約3.2万人を確認）。

## 対象期間
- 毎日：当月1日〜前日。
- 毎月1日：前月の1日〜末日（前月分の最終確定）。

## やること
1. CLAUDE.mdの3〜7章の手順で、集計してExcelを作る（scripts/aggregate.jsを使う）。
2. 上書き前に、output/backup/ に日時付きでコピーを残す。output/backup/ は最新の7個だけ残して、古いものは削除する。
3. output/流入元別申込数集計_YYYY年M月.xlsx を上書きする（この試験運用では、上書きの確認は不要）。
4. output/daily_report_YYYYMMDD.txt に、次の内容を書く（個人情報は書かない）。
   - 実行の開始・終了時刻、対象期間
   - 前日1日分の申込件数（19歳以上／18歳／17歳以下／年齢不明／合計）
   - 当月の累計申込件数
   - リード総数（Product_selling合計、エルメの友だち追加数、差分）
   - マスターに無い新しい流入元、年齢不明の人数
   - エラーや、途中で止まった点
5. Googleスプレッドシートには書き込まない（別に、手動で依頼する）。

## 止まる条件（勝手に進めない）
- エルメやGoogleのログイン画面が出たら、止まる。パスワードは入力しない。daily_report に「ログインが必要」と書いて終了する。
- 選んだボットの友だち数が約3.2万人でなければ、止まって、daily_report に書く。
- 列構成が、前回と変わっていたら、止まって、daily_report に書く。

## 使用量を抑える
- 余計な探索、長い説明、不要なスクリーンショットは、しない。
- うまくいかない操作は、3回まで試して、だめなら止めて、daily_report に書く。
- 使用量の上限に達したら、その旨を daily_report に書いて終了する。

## 最初にやること（この依頼を読んだら）
1. まず、今日（実行した日）の分を、上の手順で、1回だけ手動で実行して、動くことを確認する。
2. 動いたら、毎日11:00に、この手順を実行する定期実行を、設定する。方法は、Windowsのタスクスケジューラなど、このパソコンで確実に動く方法を、選んで、提案する。設定する前に、ユーザーに、方法と内容を見せて、許可をもらう。
3. 定期実行に必要な条件（パソコンの起動、Chromeでエルメにログイン済み）を、ユーザーに伝える。
